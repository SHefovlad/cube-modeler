# Modeler — конструктор моделей зданий для проекта X

Инструмент для **наглядного проектирования кубических моделей зданий**. Модель описывается
текстом в формате `.cubes`, а инструмент рисует её со всех сторон прямо в окне. Когда модель
готова — тот же файл `.cubes` превращается в кубы внутри Unity, **один в один** как в окне.

Зачем: раньше модель здания писали сразу в C# и проверяли запуском Unity — это долго (минуты на
итерацию) и вслепую. Здесь итерация — мгновенная: правишь текст, видишь результат, и знаешь,
что в игре будет так же.

---

## Быстрый старт (для человека)

1. Открой в VS Code файл модели, например `Examples/house.cubes`.
2. Запусти окно предпросмотра:

   ```
   cd A:\Unity\X\Modeler
   dotnet run -- --view Examples\house.cubes
   ```

3. Пиши/правь `.cubes` в VS Code и сохраняй — **картинки в окне обновятся сами** (через ~0.3 с).
4. Когда модель готова — скажи агенту «перенеси такую-то модель в игру», либо сделай это сам:
   скопируй `.cubes` в `A:\Unity\X\X\Assets\Resources\Models\` и подключи через
   `ModelCubeBuilder` (см. «Как это попадает в игру»).

```

│   ├── Resolver.cs               ← чтение .cubes + include(...)
│   ├── Watcher.cs                ← вотчер с PNG и картинкой-ошибкой (--watch)
│   ├── ParserTests.cs            ← тесты парсера
│   └── GeometryTests.cs          ← тесты геометрии
├── Examples\                     ← примеры моделей (.cubes)
│   └── house.cubes               ← игрушечный домик (эталон, на котором проверялся мост)
└── Logs\                         ← сюда пишется PNG при --render
```

## Команды

| Команда | Что делает |
|---|---|
| `dotnet run -- --view <file.cubes> [\#rrggbb]` | **основное.** Окно с 6 видами + изометрией; следит за файлом |
| `dotnet run -- --test` | Все тесты (парсер + геометрия). Должно быть `failed=0` |
| `dotnet run -- --render <file.cubes> <out.png> [\#rrggbb]` | Лист видов в PNG (для отчёта) |
| `dotnet run -- --watch <file.cubes> [out.png]` | Вотчер, пишущий PNG (устаревший режим) |
| `dotnet run -- <file.cubes>` | Разбор и печать дерева модели в консоль (отладка) |

`#rrggbb` — необязательный **принудительный цвет** для всех кубов (когда цветов в модели ещё нет).
Если не задан — каждый куб берёт свой цвет из разметки, а без цвета — серый `#9a9a9a`.

Сборка: `dotnet build`. Запуск без пересборки: добавь `--no-build`.

## Язык `.cubes` — кратко

Полное описание: **`LANGUAGE.md`**. Здесь — самое необходимое.

```
// комментарий до конца строки

cube((0, 2, 0), (4, 4, 4), (0, 0, 0), "#b05a3c")     // pos, scale, rot, [color]
{
    cube((0, 0.6, 0), (0.4, 1.2, 0.4), (0, 0, 0), "#8b3a2a")   // координаты ЛОКАЛЬНЫЕ
}
empty((0, 0, 1.6), (0, 0, 0))                        // контейнер без геометрии
{
    cube((0, 0, 0), (2, 0.2, 0.6), (0, 0, 0), "#8a8a8a")
}
```

- **`cube(pos, scale, rot, color?)`** — куб: позиция центра, размер (X Y Z), поворот в градусах
  Эйлера (порядок как в Unity), необязательный цвет `"#rrggbb"`.
- **`empty(pos, rot)`** — пустой контейнер (пивот), как `GameObject` без меша.
- **`{ ... }`** — вложенность. Ребёнок наследует позицию, скейл и поворот родителя (как в Unity).
  **Скейл родителя умножается на скейл ребёнка** — масштабируй только листья, контейнеры (`empty`)
  держи со скейлом 1, иначе дети деформируются.
- **`include("путь.cubes")`** — вставить другой файл (путь относительно текущего). Только в Modeler
  (Unity-копия парсера include пока не умеет).
- Y — вверх, единицы = юниты Unity. Пробелы и переводы строк не значимы.

### Соглашения для моделей зданий (важно!)

- **Фасад (дверь, крыльцо, парадные окна) ставь на −Z.** Изокамера в игре смотрит на грани −X/−Z;
  деталь на +Z в привычном ракурсе не видна.
- **Низ модели — на `y = 0`.** В игре модель ставится на землю по низу; не «утапливай» её и не
  поднимай выше нуля, иначе здание повиснет или уйдёт в землю.
- **Точка отсчёта — центр по X и Z.** Так модель симметрична относительно своего места.
- **Детали группируй через `empty`**, чтобы двигать часть модели целиком.
- **Кубов не жалей.** Стиль проекта — много мелких кубов (рамы окон, зубцы, столбы), «нищей версии»
  автор не принимает.

## Как это попадает в игру

Модель `.cubes` строит в Unity класс **`Assets\Scripts\Construction\ModelCubeBuilder.cs`**:

```csharp
// из строки:
var model = ModelCubeBuilder.BuildInto(cubesText, parentTransform);

// из TextAsset (.cubes в Assets\Resources\Models\):
var asset = Resources.Load<TextAsset>("Models/quarry");
var model = ModelCubeBuilder.BuildInto(asset, parentTransform);
```

Он читает ту же разметку и ставит кубы с теми же трансформами, что и окно Modeler, поэтому
**превью и игра совпадают**. Материалы — через существующий `CubeFactory` (URP/Lit, кэш по цвету).

### Проверка «превью == игра» без запуска игры

```
Unity.exe -batchmode -quit -projectPath A:\Unity\X\X `
  -executeMethod X.EditorTools.ModelCubeCheck.Render `
  -logFile A:\Unity\X\X\Logs\modelcube.log
```

Результат — `A:\Unity\X\X\Logs\modelcube_iso.png` (изометрия, те же углы, что в игре). По умолчанию
берётся `A:\Unity\X\Modeler\Examples\house.cubes`; свой файл можно указать аргументом `-model <путь>`
(добавить в конец команды). Без `-nographics` (нужен GPU для PNG).

## Разработка инструмента

- **Тесты:** `dotnet run -- --test`. Любая правка парсера/геометрии — сначала тесты.
- **Окно не собирается, потому что уже запущено:** закрой окно Modeler (файл `bin\...\Modeler.exe`
  занят) и повтори сборку.
- **Кодировка:** консоль Windows портит кириллицу. Если запускаешь команды сам, начинай с
  `chcp 65001 | Out-Null; [Console]::OutputEncoding=[System.Text.Encoding]::UTF8;`.
- **Изометрия:** углы 52° (pitch) и 45° (yaw) — те же, что у камеры в игре. Меняешь их —
  меняй и в игре, иначе превью перестанет совпадать.
- **Свет:** направленный, множители на грани (верх ×~1, бок ×0.6–0.75, низ ×0.5). Падающих теней нет.

## Инструкция для агента (передать как задачу)

> Ты работаешь с конструктором моделей проекта X.
>
> **Где:** инструмент — `A:\Unity\X\Modeler` (порядок работы в `README.md` и `LANGUAGE.md`),
> игра — `A:\Unity\X\X`, геймдизайн — `A:\Unity\X\геймдизайн\` (в том числе
> `21_Промпт_для_нейросети_модели_зданий.md` про модели зданий).
>
> **Порядок работы:**
> 1. Прочитай `A:\Unity\X\Modeler\README.md` и `LANGUAGE.md`.
> 2. Прочитай задание и референс (картинку модели) в `A:\Unity\X\референсы\`.
> 3. Напиши модель в `A:\Unity\X\Modeler\Examples\<имя>.cubes` по соглашениям модели зданий
>    (фасад на −Z, низ на y=0, центр по X/Z, много кубов).
> 4. Отрендери превью: `cd A:\Unity\X\Modeler; dotnet run -- --render Examples\<имя>.cubes Logs\<имя>.png`.
>    Сравни с референсом **измерением пропорций силуэта**, а не только на глаз — правь числа в разметке.
> 5. Повторяй шаги 3–4 сам, пока силуэт не совпадёт, **и только потом** показывай результат человеку.
> 6. Когда модель одобрена — перенеси её в игру через `ModelCubeBuilder`
>    (`Assets\Resources\Models\<имя>.cubes` + вызов из визуала здания) и проверь
>    `X.EditorTools.ModelCubeCheck.Render` (Unity batch, exit 0 + картинка).
> 7. Закоммить: инструмент — в репозиторий Modeler, игру — в репозиторий X.
>
> **Правила, за которые отвечает агент:**
> - Не выдумывать новую механику/стиль — опираться на референс и геймдизайн.
> - Не трогать существующие файлы игры без нужды; мост добавляет новые файлы.
> - Коммиты — на английском, короткие, по одному логическому шагу.
> - Если что-то не проверено — сказать честно, что именно должен проверить человек.
> - Отчитываться человеку **по-русски**, коротко: что сделал, что проверено, что дальше.
